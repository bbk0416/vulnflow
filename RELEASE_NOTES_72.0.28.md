# VulnFlow 72.0.28 release notes

Release date: 2026-08-03
SQLite schema: 46 (unchanged from 72.0.27)

## Scope

72.0.28 is a deployment-verification and maintainability release. It does not add a new customer workflow or database table. It separates the database schema implementation, hardens the production reverse-proxy trust boundary, and adds an executable HTTPS rehearsal using real local Nginx and Uvicorn processes.

## Changes

### Database schema boundary

The former 750-line `app/core/database_schema.py` module is reduced to a small compatibility facade. Version constants, migrations, triggers, search installation, and backfills now live in explicit modules:

- `app/core/schema_versions.py`
- `app/core/database_migrations.py`
- `app/core/database_triggers.py`
- `app/core/database_search.py`
- `app/core/database_backfills.py`

The SQLite schema remains 46. Existing imports through `app.core.database_schema` remain supported.

### Reverse-proxy client identity

The production Nginx configuration now overwrites `X-Forwarded-For` with the actual edge connection address instead of appending a client-supplied forwarded chain. This closes a configuration path where a caller could spoof the source used by application login rate limiting once proxy headers were trusted.

Duplicate security headers from the upstream application are hidden at the proxy boundary where Nginx sets the authoritative value.

### Live TLS proxy rehearsal

`scripts/live_tls_proxy_rehearsal.py` generates a temporary one-day self-signed CA certificate and starts local Nginx and Uvicorn processes using the production security profile. The recorded rehearsal verifies 14 controls:

- verified HTTPS readiness;
- HTTP-to-HTTPS redirect;
- TLS 1.2 and TLS 1.3 acceptance;
- TLS 1.1 rejection;
- HTTPS login page;
- Secure, HttpOnly, SameSite session and CSRF cookies;
- database-backed login and authenticated request;
- HSTS and frame protection;
- hidden Nginx version;
- rejection of a spoofed forwarded client address.

### Container-equivalent rehearsal

The host process rehearsal now follows split control/project storage, explicit default-project API-token scope, non-root UID 10001 execution, read-only source, and two restart cycles. It passed 26/26 checks in this workspace.

## Limits

- The Docker engine was unavailable, so no current image build, Compose network, Docker volume driver, or container health-status execution is claimed.
- The TLS certificate was generated by a temporary local rehearsal CA; public DNS, ACME or enterprise-PKI issuance, renewal, and revocation were not exercised.
- External backup media, SMTP, Jira, and authorized customer scanner files were not exercised.
- The live rehearsal is a deployment contract check, not a penetration test, certification, or production approval.
