# Windows external-validation remediation

VulnFlow 72.0.56 is based on evidence collected from the v45 Windows External Validation Run Kit on Windows 10 build 26200 with CPython 3.13.14.

## Evidence-derived failure classes

The v45 run collected 610 public tests: 482 passed, 120 failed, and 8 were skipped. The failures were not a single readiness score and were separated into these classes:

1. **Portable product defect:** SQLite backup publication used `os.fsync()` on a read-only descriptor. Windows returned `OSError: [Errno 9] Bad file descriptor`, cascading into backup, job, and soak tests.
2. **Unsupported runtime boundary:** signed offline deployment v95-v104 depends on POSIX ownership/mode bits, advisory locks, symlinks, atomic rename behavior, and directory fsync. Windows is not a supported execution platform for that subsystem.
3. **Validation-tool portability:** live TLS and Compose rehearsals depended on an external OpenSSL executable, and short-form bind mounts were unsafe for drive-letter paths.
4. **Test-harness defects:** one path assertion used POSIX separators; browser E2E used an ambiguous locator and left Uvicorn output in an undrained pipe.
5. **Dependency closure drift:** the Windows wheelhouse exposed an omitted `idna==3.17` runtime closure pin.

## Remediation contract

- SQLite snapshots retain integrity checking, a durability barrier, atomic publication, and parent-directory fsync where the platform supports it.
- TLS rehearsal certificates are generated by `cryptography`; no OpenSSL command-line executable is required.
- Compose bind mounts use mapping syntax with explicit source, target, and read-only fields.
- Rehearsal failures still create the required JSON result and remain failed or unavailable; they are never promoted to pass.
- Only the offline-deployment cases that require POSIX filesystem semantics are reported as Windows skips with an explicit reason; portable cryptographic and format checks continue to run.
- Browser server logs are file-backed so child output cannot fill a Windows pipe and stall navigation.
- The runtime lock, packaged dependency manifest, and SBOM include `idna==3.17`.

## Remaining external work

This release is not a claim that Windows validation has passed. The corrected source and runner must be executed again on Windows. Docker Desktop must be running for production Compose validation, Chromium/Chrome must be unrestricted for E2E, and an approved anonymized customer scanner corpus remains separately required.
