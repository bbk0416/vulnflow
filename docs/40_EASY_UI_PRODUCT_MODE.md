# Easy UI product mode

VulnFlow의 운영 엔진은 다중 스캐너 조정, 우선순위 정책, 승인, 증거, 감사, 복구까지 포함합니다. 하지만 첫 사용자는 이 기능을 모두 동시에 이해할 필요가 없습니다. 이 문서는 기본 화면이 따르는 제품 원칙을 설명합니다.

## 기본 사용자 흐름

```text
CSV 결과 가져오기
  → 처리 전: 담당자와 목표일 지정
  → 조치 중: 패치·설정 변경 수행
  → 확인 요청: 조치 근거와 증거 제출
  → 완료: 검증 승인
```

화면에는 내부 상태값 대신 다음 한글 이름을 우선 표시합니다.

| 내부 상태 | 기본 화면 |
|---|---|
| `OPEN` | 처리 전 |
| `IN_PROGRESS` | 조치 중 |
| `MITIGATED` | 확인 요청 |
| `RISK_ACCEPTED` | 예외 승인 |
| `CLOSED` | 완료 |

내부 상태값과 상세 점수는 API, 감사, 데이터 조정 기능에서 유지합니다. 화면 단순화는 저장 모델이나 승인 경계를 약화시키지 않습니다.

## 정보 노출 원칙

기본 화면에는 사용자의 다음 행동에 필요한 정보만 먼저 표시합니다.

- 취약점과 대상 자산
- 처리 우선순위
- 현재 진행 단계
- 담당자와 목표일
- 다음 작업 버튼

다음 기능은 `관리자 메뉴`, `상세 필터`, `세부 정보` 아래에 둡니다.

- 다중 스캐너 충돌 조정
- SBOM·VEX와 공급망 기능
- 정책·작업 큐·웹훅
- 데이터 생명주기와 원천 관측
- 증거 보관 사슬과 시스템 복구

## 상세 화면 원칙

상세 화면은 기술 점수보다 현재 해야 할 일을 먼저 보여줍니다.

1. 진행 단계를 네 칸으로 표시합니다.
2. 현재 상태에 맞는 안내 문구와 체크리스트를 보여줍니다.
3. 담당자, 목표일, 조치 메모를 한 폼에서 입력합니다.
4. `확인 요청` 상태일 때 검증 요청 폼을 노출합니다.
5. 우선순위 계산과 스캐너 원천은 접힌 세부 정보로 이동합니다.

## 제품 검증에서 확인할 지표

실제 고객 파일럿에서는 기능 수보다 다음 결과를 측정합니다.

- CSV 업로드부터 첫 담당자 지정까지 걸린 시간
- 신규 사용자가 도움 없이 완료한 작업 비율
- 기한 초과 항목 감소율
- 조치 증적을 찾는 데 걸린 시간
- 기존 Excel 보고서 작성 시간 대비 절감률

이 지표가 개선되지 않는 기능은 기본 화면에 추가하지 않습니다.
