# 보안·개인정보 설계

- 기본 루프백 바인딩
- viewer·operator·approver·admin 역할 기반 Basic 인증
- 자동화용 Bearer API 토큰과 브라우저 사용자 계정 분리
- 쓰기 API는 Bearer 토큰만 허용
- 인증 예외 상태 엔드포인트는 최소 정보만 반환
- 인증된 사용자·API 토큰 이름을 감사 actor로 기록
- 브라우저 POST 요청 CSRF 검증
- CSP·프레이밍 차단·캐시 금지·MIME 스니핑 방지
- 파일 크기·행 수·필드 길이·CVE·수치·날짜·상태 검증
- CSV 수식 삽입 방어와 HTML 출력 이스케이프
- SQLite 파라미터 바인딩, WAL, busy timeout, trusted_schema 비활성화
- 행 버전 기반 동시 수정·승인 충돌 감지
- 복원 파일의 헤더·무결성·필수 스키마·트리거 검사
- 복원 직전 자동 안전 백업과 오류 시 롤백
- 웹훅 secret 비저장, HMAC-SHA256 서명, HTTP 리다이렉트 차단
- 원격 웹훅은 기본적으로 HTTPS만 허용
- 웹훅 원자적 전송 임대로 중복 동시 발송 방지
- 요청 ID와 JSON 구조 로그에 비밀번호·토큰·웹훅 secret 미기록
- Docker 비루트 사용자

운영용 비밀이나 직접 식별 개인정보를 입력하지 않는 것을 기본 원칙으로 합니다. Basic 인증을 네트워크에서 사용할 때는 TLS 역방향 프록시가 필수입니다. 중앙 인증, MFA, 외부 감사로그가 필요한 조직 환경은 후속 OIDC·SAML 연동 전까지 제한적으로만 사용합니다.


## 백그라운드 작업 보안

- 작업 생성은 역할 검사와 API Bearer 요구사항을 그대로 적용합니다.
- 작업 목록·상세 API는 CSV 원본 행을 반환하지 않습니다.
- payload는 로컬 SQLite 백업에 포함되므로 민감한 원본 CSV를 입력하지 않습니다.
- 임대 소유자가 아닌 워커는 heartbeat·완료·실패 상태를 기록할 수 없습니다.
- admin만 작업 취소와 실패 작업 재시도를 수행합니다.
